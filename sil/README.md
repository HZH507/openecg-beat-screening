# 硬件链路仿真（软件在环 SIL）

本模块在 DS2 全部 49,705 拍上比较理想通路、仅量化+链路、设备链路和设备链路的整数时延对齐分支。四路使用同一个冻结二分类模型 `results/workpoint_cv_v2/final_binary.pt` 与完整精度阈值 0.5878590941429138；不训练模型，不根据 SIL 结果调整阈值。

```text
原始数字记录
  ├─ 理想通路：现有数字预处理 → 切分与逐拍标准化 → 分类
  ├─ 仅量化+链路：ADC → 分包与丢包 → 重组 → 同上数字预处理 → 切分与分类
  └─ 设备链路：因果 AFE → ADC → 分包与丢包 → 重组 → 同上数字预处理
               ├─ 按原 R 峰位置切分 → 分类
               └─ 离线互相关估计整数 lag → 按正确方向移位 → 切分 → 分类
```

## 方法与文件

- `afe.py`：0.5 Hz 二阶高通与 40 Hz 四阶 Butterworth 低通，使用 `sosfilt` 因果串联。
- `adc.py`：11 bit、±5 mV 量化；LSB 为 10/(2¹¹−1) mV，约 4.89 µV；量化前叠加 ±0.5 LSB 均匀抖动。
- `link.py`：20 采样/包，设定 1% 丢包，缺包采用上一包末样本保持。20 ms 为缓冲设定记录；重组按时间戳，不据此额外平移信号。
- `run_sil.py`：读取 DS2 记录并执行四路评价。现有数字预处理为 0.5–40 Hz 零相位带通与 60 Hz 陷波，之后按原 R 峰切分并逐拍标准化，输入冻结分类器。

对齐分支按每条记录的理想波形与设备波形互相关估计整数延迟。正 lag 表示设备信号滞后，故将设备信号左移；负 lag 表示超前，故右移，边界以端值填充。原脚本的移位方向相反，本轮已修正，并经授权仅重跑 SIL。理想与未对齐设备通路复现原指标，正确整数对齐未恢复理想通路 AUC；具体指标以本轮 JSON 和逐拍缓存为准。

固定阈值下 Se/Sp 的变化说明工作点迁移，未来设备应用需在独立开发数据上校准。本轮未实施这种校准，也不能由 Se/Sp 的变化直接推出“概率整体下移”。

新增组件消融绕过 AFE，保留相同的 11 bit 量化、分包、1% 丢包与数字预处理。仅量化+链路的 AUC 为 0.8530（相对理想为 −0.0027），Se 为 72.75%，接近理想通路的 0.8558 / 72.27%；加入 AFE 后 AUC 为 0.8456、Se 为 62.14%。该组设置的主要损失来自 AFE 与数字带通串联造成的高频衰减，量化和传输不是主因。整数时延对齐后 AUC 仍为 0.8435，剩余差异还包含频率相关相位与形态变化。该消融只对照量化+链路组合与加入 AFE 的完整通路，不把量化、分包和丢包逐项拆开。

## 边界与推理范围

- 源数据本身已是 360 Hz 数字记录，**未模拟采样前混叠**。
- 丢包率、包大小和缓冲是设定值，不是设备实测值。
- 互相关对齐是离线参考辅助分析，尚未验证真实设备时间戳或 R 峰检测器的补偿效果；单一整数移位也不能消除所有频率相关相位变化。
- 现有数字预处理使用未来样本，本模块不能证明端到端实时性。
- 本模块属于软件在环仿真，不能替代实物联调。
- 原干净 DS2 主评价的单次推理缓存和审计保持不变。SIL 是额外的四通路推理，包含理想通路复算；先前方向修正后获授权重跑 SIL，随后用户新增组件消融并重跑，因此不能把“原主评价一次”描述成全项目从未再次推理 DS2。

## 在新工作副本中复现

准备原始 MIT-BIH 记录、冻结模型和项目环境后，在新工作副本的根目录运行：

```powershell
python sil/run_sil.py
```

脚本会覆盖该工作副本的 `results/sil/`；现有结果应先备份。重建报告仅读现成输出，无需再次运行 SIL。

输出到 `results/sil/`：

- `sil_metrics.json`：四路 AUC、Acc、Macro-F1、Se、Sp、混淆计数，延迟、概率摘要及逐拍缓存哈希；`quant_link` 为绕过 AFE 的消融通路。
- `sil_predictions.npz`：同序的 `y`、`prob_ideal`、`prob_quant_link`、`prob_sil`、`prob_aligned`、`record` 和 `sample`。可直接核对指标，无需重新推理。
- `sil_afe.png`：AFE 幅频响应与片段波形对照。
- `sil_roc.png`：四路 ROC 曲线。

报告构建清单与代码包清单将本轮 JSON、逐拍缓存和四个源码绑定 SHA-256。旧反向移位结果只在项目备份和修订历史中保留，不作为当前报告结果。
